2 · What you built

Know, alert, recover

Know

  • A run history: one row for every step of every night
  • Four health numbers, each with a target
  • Two new tests: a file arrived on time, and a price is believable

Alert

  • A callback: Airflow runs it when a task fails or publish succeeds
  • Each alert goes to the person who can act: page, ticket or message
  • A problem is sent once, and closed when it is gone

Recover

  • Fix the source, never the warehouse
  • Run only that night again, with one command
  • A changed file is loaded again. A file that did not change is skipped

3 · Alerts, night by night

alerts, not

One alert for every failed test on every night would have been messages. People stop reading that many. That is alert fatigue. So each problem is sent once, when it is new. After that it is counted as still open, and it is closed when it is gone.

4 · Health

Four numbers, each with a target

"On time" is a number now: the share of sales files that arrived by 01:00. A number you measure is an SLI. The target for it is an SLO. This week the target was missed, by one late file and one file that never came.

6 · What you learned

Five things

  1. A check that nobody hears about protects nobody.The gates of milestone 4 were right all week. The head of retail operations still found out on Monday.
  2. Say "on time" as a number, with a target, and measure it.39 of 41 files by 01:00 is 95.1%. The target is 98%. Now everyone can see the miss.
  3. An alert goes to the person who can act, once, with what to do.A page wakes someone. A ticket is for today. A message can wait. Ten alerts are read. Seventy are not.
  4. Never repair in the warehouse. Fix the source and run the day again.The tables are built again from the raw rows every night, so a hand fix is gone tomorrow.
  5. A safe re-run makes recovery boring, and boring is the goal.Run the night again and nothing is counted twice. The number equals the answer key.

    What this milestone needs

    Nothing new is installed. Git, Python 3.12 or later, uv and Docker, as in milestone 1. No API key, no cloud account, no AI. The alerts need no service: they go to a table and a log file.

    From the project folder

    uv sync
docker compose up -d --build   # the warehouse, and Airflow

    To run one night, and its alerts, as a plain program:

    uv run python -m store_systems deliver --through 2026-08-24
cd src/m5_know_alert_recover
uv run python -m lotus_pipeline run --day 2026-08-24
uv run python -m lotus_pipeline alerts --day 2026-08-24
uv run pytest                                  # this milestone's tests

    To fix a store and run one night again, read RUNBOOK.md. When you are done: docker compose down.
