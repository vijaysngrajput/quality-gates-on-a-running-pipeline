5 · What you learned

Five things

  1. A check is only as good as the question behind it.Unique on which columns? Empty in which rows? The common version passes. The careful version catches the fault.
  2. Most useful checks need the data prepared first.A join, a total, a comparison. That is why one-line checks on one column miss so much.
  3. A valid value can still be wrong.Accuracy needs a second source that saw the same thing. For Lotus it is the till's own total.
  4. A limit comes from the data.A normal day depends on the store and on the weekday. One fixed number is wrong for somebody.
  5. A check that cries wolf gets switched off.So prove that it stays silent on what is not wrong: a holiday, a closed store, a real sale of 400 bottles.

Set up

What this milestone needs

Nothing new. Git, Python 3.12 or later, uv, and Docker, as in milestone 1. No API key, no cloud account, no AI.

From the project folder

uv sync                          # makes the virtual environment
docker compose up -d --build     # starts the warehouse and Airflow

To run the bonus week and then your checks, as plain programs:

uv run python -m store_systems deliver --through 2026-08-30
cd src/m2_checks_with_a_reason
uv run python -m lotus_pipeline run --day 2026-08-30   # the nightly run; repeat for each night
uv run python -m lotus_pipeline inspect                # every check, and what it found
uv run pytest                                          # runs this milestone's tests

When you are done: docker compose down.
