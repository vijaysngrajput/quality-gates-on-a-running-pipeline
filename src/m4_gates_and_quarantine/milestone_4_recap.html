5 · What you learned

Five things

  1. dbt holds the rule. Airflow runs it and acts on the result.The rule is a query in a file. The gate is a task that other tasks wait for.
  2. A failed check must do something.Stop the run, set the rows aside, or warn. Choose for each check, and write the choice next to the rule.
  3. Where a gate stands decides what it can protect.Only the first gate can still see a file's own columns. Only the last can see whether the whole day adds up.
  4. Set bad rows aside with a reason, and let the good rows go on.Then make the output say what it is missing. A number that hides a gap is still a wrong number.
  5. Test the tests.Plant the fault and watch its gate catch it. Then run clean data and watch every gate stay quiet.

Set up

What this milestone needs

dbt is new. It is installed into the project's virtual environment by uv sync, and into the Airflow image by a rebuild. Git, Python 3.12 or later, uv and Docker, as in milestone 1. No API key, no cloud account, no AI.

From the project folder

uv sync                        # adds dbt to the virtual environment
docker compose up -d --build   # the warehouse, and Airflow with dbt inside

To run one night through the gates as a plain program:

uv run python -m store_systems deliver --through 2026-08-24
cd src/m4_gates_and_quarantine
uv run python -m lotus_pipeline run --day 2026-08-24              # all eight steps
uv run python -m lotus_pipeline gate-clean --day 2026-08-24       # one gate
uv run python -m lotus_pipeline dbt test --select test_type:unit  # the unit tests
uv run pytest                                                     # this milestone's tests

When you are done: docker compose down.
