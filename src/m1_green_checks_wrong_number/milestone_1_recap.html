5 · What you learned

Five things

  1. Green checks do not mean right data.A check answers only the question it asks. Five green checks let a wrong number reach every store.
  2. A check needs a reason.Say who uses the table, and what goes wrong for them when it is wrong. A check with no such answer is deleted.
  3. Rank the tables by harm before you write any check.The table that pays people comes first. Not every worry deserves a check.
  4. Say what one row means, then read the table, before you check it.Rows per store per day, the smallest and largest values, the empty cells. Each surprise is a candidate check.
  5. Work the number out by hand.Without an answer key you cannot tell a right number from a wrong one.

Set up

What this milestone needs

Git, Python 3.12 or later, uv, and Docker. No API key, no cloud account, no AI. Everything is free and runs on your computer. The milestone's README installs Docker with you, step by step, on macOS, Windows and Linux.

From the project folder

uv sync                          # makes the virtual environment
docker compose up -d --build     # starts the warehouse and Airflow

Airflow's page is at http://localhost:8080. To run one night yourself, as a plain program:

uv run python -m store_systems deliver --through 2026-08-24
cd src/m1_green_checks_wrong_number
uv run python -m lotus_pipeline run --day 2026-08-24   # prints the bonus report
uv run pytest                                          # runs this milestone's tests

When you are done: docker compose down.

Every number on this page is written by lotus_pipeline/flow_data.py from a real run of this milestone's code, and a test checks that they still match. All data is fictional. Lotus Retails does not exist.
